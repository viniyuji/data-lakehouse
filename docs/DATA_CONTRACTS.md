# Data Contracts & Schema Specification

> **Rule for AI Agents**: Any schema change MUST keep all four layers aligned: (1) `postgres/init.sql`, (2) `generate_data.py`, (3) `debezium/connector-config.json`, and (4) `flink/sql/job.sql`.

---

## 1. Source Layer — PostgreSQL (`lakehouse.public`)

Database: `lakehouse` | Schema: `public` | WAL Requirement: `ALTER TABLE <name> REPLICA IDENTITY FULL;`

### `public.clients`
- `id`: `SERIAL PRIMARY KEY`
- `client_name`: `VARCHAR(255) NOT NULL`
- `client_number`: `VARCHAR(50) NOT NULL`
- `client_address`: `TEXT NOT NULL`
- `document`: `VARCHAR(50) NOT NULL`

### `public.products`
- `id`: `SERIAL PRIMARY KEY`
- `product_name`: `VARCHAR(255) NOT NULL`

### `public.sales`
- `id`: `SERIAL PRIMARY KEY`
- `client_id`: `INTEGER NOT NULL REFERENCES clients(id)`
- `product_id`: `INTEGER NOT NULL REFERENCES products(id)`
- `unity`: `INTEGER NOT NULL` *(quantity of units sold)*
- `value`: `NUMERIC(12, 2) NOT NULL` *(unit price)*
- `sale_date`: `TIMESTAMPTZ NOT NULL DEFAULT NOW()`
- `status`: `VARCHAR(50) NOT NULL` *(domain generated by `generate_data.py`: `'PENDING'`, `'PAID'`, `'SHIPPED'`, `'CANCELLED'`)*

### `public.debezium_heartbeat` *(operational table — not exposed as a business CDC topic)*
- `id`: `INTEGER PRIMARY KEY`
- `updated_at`: `TIMESTAMPTZ NOT NULL DEFAULT NOW()`
- Included in publication `dbz_lakehouse_publication` so Debezium's `heartbeat.action.query` (`10s` interval) advances PostgreSQL's `confirmed_flush_lsn`, while excluded from `table.include.list` so it does not pollute business topics.

## 2. CDC Ingestion & Kafka Retention Contracts

- **Connector**: `postgres-lakehouse-connector` (`io.debezium.connector.postgresql.PostgresConnector`, `plugin.name = pgoutput`)
- **Batch & Heartbeat Settings**:
  - `max.batch.size = 2048`, `max.queue.size = 8192`, `poll.interval.ms = 500`
  - `heartbeat.interval.ms = 10000` + `heartbeat.action.query` on `public.debezium_heartbeat` $\rightarrow$ emits LSN heartbeats to `__debezium-heartbeat.lakehouse`
- **Topic Naming & Lifecycle Matrix** (enforced idempotently by `kafka-init` via `kafka-configs.sh --alter`):

| Topic | Role | `cleanup.policy` | Retention / Compaction Limits | Rationale |
| :--- | :--- | :--- | :--- | :--- |
| `lakehouse.public.clients` | Dimension CDC | `compact` | `segment.bytes=50MiB`, `min.cleanable.dirty.ratio=0.1`, `delete.retention.ms=1h` | Preserves latest state of every `client.id` forever for Flink join replays |
| `lakehouse.public.products` | Dimension CDC | `compact` | `segment.bytes=50MiB`, `min.cleanable.dirty.ratio=0.1`, `delete.retention.ms=1h` | Preserves latest state of every `product.id` forever for Flink join replays |
| `lakehouse.public.sales` | Fact CDC | `delete` | `retention.ms=24h`, `retention.bytes=512MiB`, `segment.bytes=50MiB` | Bounds raw event log growth while keeping a 24h replay window |
| `sales_enriched` | Flink Upsert Sink | `compact,delete` | `retention.ms=24h`, `segment.bytes=50MiB`, `min.cleanable.dirty.ratio=0.1`, `delete.retention.ms=1h` | Deduplicates rapid updates per `sale_id` and expires records older than 24h |
| `__debezium-heartbeat.lakehouse` | LSN Heartbeat | `compact` | `segment.bytes=10MiB`, `min.cleanable.dirty.ratio=0.01` | Keeps only the latest connector heartbeat |

- **Envelope Format**: Schema-less Debezium JSON (`key.converter.schemas.enable = false`, `value.converter.schemas.enable = false`).
  - **Key payload**: `{"id": <int>}`
  - **Value payload**:
    ```json
    {
      "before": { ... },
      "after": { ... },
      "source": { ... },
      "op": "c | u | d | r",
      "ts_ms": 1795625426986
    }
    ```
- **Type Serialization Rules**:
  - `NUMERIC(12, 2)` $\rightarrow$ JSON floating-point number (e.g., `47.71`) via `"decimal.handling.mode": "double"`.
  - `TIMESTAMPTZ` $\rightarrow$ ISO-8601 UTC string (`"2026-11-25T16:50:26.986932Z"`).

## 3. Stream Transformation Layer — Flink SQL (`sales-cdc-enrichment`)

Defined in `flink/sql/job.sql`.

### Source Table Mappings (`connector = 'kafka'`, `format = 'debezium-json'`)
- `clients_cdc` $\leftarrow$ `lakehouse.public.clients` (`PRIMARY KEY (id) NOT ENFORCED`)
- `products_cdc` $\leftarrow$ `lakehouse.public.products` (`PRIMARY KEY (id) NOT ENFORCED`)
- `sales_cdc` $\leftarrow$ `lakehouse.public.sales` (`PRIMARY KEY (id) NOT ENFORCED`)
  - **Important**: Column `` `value` `` MUST be backtick-quoted (`DECIMAL(12, 2)`).
  - `sale_date` is ingested as `STRING` (preserving Debezium's ISO-8601 UTC representation).

### Transformation Semantics
- Performs stateful streaming `INNER JOIN`s:
  - `sales_cdc.client_id = clients_cdc.id`
  - `sales_cdc.product_id = products_cdc.id`
- Derives:
  - `status`: `UPPER(s.status)`
  - `unit_value`: ``s.`value` `` (`DECIMAL(12, 2)`)
  - `total_value`: ``CAST(s.unity * s.`value` AS DECIMAL(14, 2))``
- **Determinism Rule**: Projections feeding an updating/changelog sink MUST remain deterministic (do NOT inject `PROCTIME()` or `CURRENT_TIMESTAMP` directly into the non-windowed changelog `SELECT`).

## 4. Sink Layer — Enriched Kafka Topic (`sales_enriched`)

- **Topic**: `sales_enriched`
- **Connector**: `upsert-kafka` (`key.format = 'json'`, `value.format = 'json'`)
- **Primary Key / Message Key**: `{"sale_id": <int>}`
- **Changelog Semantics**:
  - `INSERT` emits a key/value JSON record.
  - `UPDATE` in PostgreSQL (e.g., `sales.status` changing from `PENDING` to `PAID` or `SHIPPED`, or a client/product attribute changing) causes Flink to emit a retract tombstone (`null` value for `{"sale_id": <int>}`) followed immediately by the updated JSON value for `{"sale_id": <int>}`.
  - Downstream consumers reading `sales_enriched` as a compacted/upsert log MUST treat `null` payloads as deletions/retractions per key.

### `sales_enriched` Value Payload Example

{
  "sale_id": 5,
  "sale_date": "2026-11-25T16:50:27.997709Z",
  "status": "SHIPPED",

  "unit_value": 154.58,
  "total_value": 463.74,
  "client_id": 10,
  "client_name": "Brittany Boyd",
  "client_number": "650-875-9114",
